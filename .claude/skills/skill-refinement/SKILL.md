# Skill Refinement

A landed change does not only change code. It quietly invalidates the prose that
described the old world: the other vault skills, the generated mandate blocks in
each `CLAUDE.md`, and the plan/handoff documents under `docs/`. Nothing else in
this shop is responsible for noticing that. This skill is.

Its rule, above all others: **verify every named symbol against the tree before
you believe the prose.** A document is not stale because it feels old; it is
stale because something it names no longer exists, or now means something else.

## When to run it

- After any change that renames, deletes, or re-homes a concept — an area, an
  epic, a tag, a route, a config knob, a file, a pass.
- After a numbered plan's last step lands.
- Whenever a card was created with a dead tag, an epic name in `area:`, or any
  other symptom of an AI reading stale instructions.
- On garbage time, as the standing low-effort audit.

## Scope — exactly three surfaces

1. **Every enabled skill in the vault.** List with `GET /v1/skills`; fetch each
   body with `GET /v1/skills/{id}` (the list omits bodies). Disabled skills are
   out of scope — they are not in anyone's context.
2. **The generated mandate block in each `CLAUDE.md` sync target.** Read the
   targets from `GET /v1/app-config` (`skill_sync_targets`).
3. **`docs/*.md` in the repo the change touched.**

Nothing else. Source comments, test names, and commit messages are not this
skill's business.

## What counts as stale

Each check is mechanical. Run it; do not eyeball it.

- **A named symbol that no longer exists.** A route, file path, class, function,
  or config knob quoted in prose. Grep the tree for it. `runner.dart` contains a
  NUL byte and reads as binary to grep — use `grep -a` or `awk` there, or you
  will conclude a live symbol is dead.
- **An area or epic that no longer exists.** Check the live taxonomy in
  `GET /v1/app-config` (`areas`, `epics`). Note that `tagColors` there is a
  colour map, not a registry — an absent tag is not evidence of anything.
- **A retired tag.** The canonical list is code, not config: the `retiredTags`
  const in `packages/kaizend-server/lib/migrations/area_taxonomy_map.dart`.
  Grep the three surfaces for every entry in it. A retired tag named as a *live*
  tag is stale; a retired tag named in an explanation of why it was retired is
  not.
- **A workflow whose seam moved.** The prose describes step B calling step C,
  but C now lives behind a different pass, column, or endpoint.
- **A numbered plan whose steps are all done.** It stops being a plan and
  becomes a record; say so at the top rather than leaving future readers to
  execute finished work.

## What does not count

Do not rewrite prose that is still true. Specifically:

- Rationale and history — *why* a thing was removed, what misfired — stays. It
  is the reason nobody re-adds it.
- A deliberately frozen document (a dated handoff, a session log) is a record of
  a moment. It gets a **status banner** at the top saying what superseded it and
  when. It does **not** get rewritten to match today; rewriting it destroys the
  only copy of what was true then.
- Wording you would merely have phrased differently.

An audit that returns "no false positives" is worth more than one that returns a
long list. Report file and line for each finding.

## How to fix what you find

- **Skills:** edit through `PUT /v1/skills/{id}`. Never touch the copies under
  `.claude/skills/` — those are sync output and the next sync overwrites them. A
  card *generated by* a skill-refinement finding, when its own acceptance is
  that PUT, needs the `manual` tag at creation — a headless worker has no
  `KAIZEND_TOKEN` to make that call and will burn a round finding that out
  before parking itself STUCK. See story-discipline's "How a story is
  written" for the general rule.
- **`CLAUDE.md` mandate blocks:** never hand-edit. They are regenerated by
  `SkillSync` on every vault write. Any successful `POST`/`PUT` to `/v1/skills`
  re-syncs every target; that is how the block gets fixed.
- **`docs/*.md`:** ordinary edits in the repo, except frozen documents, which get
  the banner described above.

## Output

A concrete list, one line per finding:

```
<file>:<line> — <the stale claim> → <what is true now, with the symbol you verified>
```

Then the edits, then a one-line note of what you checked and found clean, so the
next run knows the audit was real.
